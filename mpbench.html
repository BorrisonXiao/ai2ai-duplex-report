Definitions, caveats and sources

Coverage of the published evaluation protocol, not every task that could be built from the data. Model interface describes the intended input/output route; it does not imply that every capability of that model is evaluated.

Multi-party means a group setting, in text or audio. Synthetic describes the conversation/voice material; Mixed combines generated and human material. Target model: Text = text input/output; Audio→text = audio input, text/JSON output; Voice = voice interaction; Duplex = concurrent listening and speaking. Alternative adapters and text controls are listed below.

Content = semantic response scoring; Tools = call correctness; Timing = participation or response timing; User interruption = yielding/recovery when a user interrupts; Backchannels = generation or tolerance of brief acknowledgments; Speech quality = acoustic/prosodic scoring. A Yes does not imply comprehensive coverage. MSI bystander interference is distinct from directed user interruption. Source check: 2026-10-19.

MP-Bench

Multi-speaker setting
Yes: 3 simulated human speakers plus the agent; discussion and turn-based games.
Data origin
Synthetic LLM-authored dialogue rendered with ElevenLabs conversational TTS; human-verified tasks. Main recordings have no overlapping speech or background noise.
Input, protocol and model interface
A complete audio task is streamed to voice agents. Primarily realtime speech-in/speech-out; non-realtime voice and text-only controls are also evaluated.
Semantic response scoring
Yes: comprehension/speaker-name accuracy and response appropriateness from transcribed output; discussion appropriateness measures consistency, not factual accuracy.
Tool-call scoring
No dedicated tool-call task or call validator.
Duplex and timing coverage
Limited: speak/stay-silent decision after the task clip and response-onset latency for realtime voice agents.
What the scores do not establish
No dedicated interruption/correction-recovery, backchannel, overlapping-input or speech-fluency/quality test. Streaming input alone does not establish these behaviors.

At a glance

MP-Bench evaluates a voice agent as a participant in a four-person spoken conversation: three simulated humans and the agent. The official task set has two scenarios and 927 tasks.

927audio tasks
11.73 htotal input audio across 927 files
396 / 543understanding tasks ask for speaker identity
128 / 128turn-based tasks labeled speak / stay silent

Audio files in the downloaded release are mono 16 kHz PCM. The task manifest records scenario family, whether the agent should speak, and—in speaker-name cases—the expected name. The full benchmark and its checksums remain in the project workspace; the published page contains only these three preview clips.

Two scenarios, three evaluation groups

A task is one complete multiparty recording, not one independent test per speaker turn. The paper reports a mean recording length of 45.6 ± 11.5 seconds and 8.4 ± 2.1 conversation turns (paper task statistics).

Understanding · 543 tasks

Follow who said what

Discussion clips end with a comprehension question about the conversation. A speaker-name subset asks which participant made a statement; there are 396 such labels in this release.

Discussion behavior · 128 tasks

Answer when invited

Participants debate a question and directly invite the agent to answer or settle the disagreement. These tasks test whether the agent gives an appropriate response.

Turn-based behavior · 256 tasks

Speak on the correct turn

Word-chain and number games assign the agent a follower role. The last game speaker and team roles determine whether the agent should answer after the clip or stay silent. Half of these tasks call for a response and half for silence, so turn-taking accuracy has a 50% chance baseline.

No fixed-size chunking is described

The paper says it streams each full input recording to real-time audio agents, but does not give a fixed audio chunk size or score every internal speaker change as a separate decision. For each task, the expected action is one binary label at the end of the full clip: speak or stay silent. The official reproduction instructions append 30 seconds of silence after the clip so a response can be captured.

Protocol and interpretation

Turn-taking accuracy

Did it take the expected action?

For audio output, Parakeet streaming ASR supplies word timestamps. If any generated word starts after the final input word, the task is marked “spoke”; otherwise it is “silent.” That binary action is compared with the task’s should_speak label, and accuracy is the percentage of task labels matched. The 128 Discussion behavior tasks all expect a reply, so 100% there is not a demanding test. The 256 game tasks are balanced 128/128, giving a 50% chance baseline.

Appropriateness accuracy

Was the action and reply suitable?

A task counts as appropriate only when the agent takes the right turn and its response fits. For Discussion, the judge checks logical consistency with the debate—not factual truth. For a game, it checks the assigned rules; silence is the right action on a negative turn.

Understanding accuracy

Did the answer match the reference?

Each of the 543 understanding questions gets a correct/incorrect verdict against its reference answer. The paper describes GPT-5 as its LLM judge; for its text baseline it says the generated text is compared directly to the reference answer. The speaker-name score is a 396-question subset with one of three human speakers as the answer; 33.3% is random guessing. This is answer accuracy, not word error rate. The pinned repository supplies answer and name-judging prompts.

Latency is separate from accuracy: for a real-time audio agent it is the mean delay from the final input word to the first generated word, over non-silent responses. It is not reported for text-only references. See the paper’s evaluation definitions (§3.3). The official scorer and prompts are linked in the repository’s timestamp detector, metric code, understanding judge, and turn-based judge.

The three clips illustrate task formats. Paper reference results below were not rerun locally and do not measure DuplexOmni.

Text-only LLM reference: transcript versus speaker labels

The paper uses Gemini-3.1-Pro as a text baseline. It gets the task transcript as text rather than streaming audio; no fixed-size audio chunks or incremental transcript updates are described, and no response latency is reported. In ASR-only, the input is the paper’s ground-truth ASR transcript without per-turn speaker labels. In SpkD-ASR, the same transcript also includes the ground-truth anonymized speaker ID on every turn, approximating a cascaded system with perfect diarization.

ASR-only

Transcript, no diarization

Tests what a strong LLM can answer when the transcript is available but who-spoke-which-turn labels are not supplied.

SpkD-ASR

Transcript plus oracle speaker IDs

Adds the correct anonymized speaker label for each turn. This is an upper-bound reference for the diarization component, not the output of a practical diarization system.

What the comparison suggests

Adding oracle speaker IDs raises speaker-name accuracy from 27.27%—below the 33.3% three-speaker chance baseline—to 93.94%. Turn-based turn-taking rises from 49.22%, essentially the 50% balanced-label baseline, to 98.44%. This supports the authors’ diagnosis that speaker attribution is a major bottleneck for this model on these tasks; it does not show that a real ASR-plus-diarization pipeline will attain the oracle score.

Table 3’s overall understanding accuracy moves from 4.79% to 87.48% (+82.69 percentage points). The paper’s separate 66.67-point comparison (93.94 minus 27.27) is for the speaker-name subset. Discussion turn-taking is 100% in both text settings because every Discussion behavior item explicitly requires a reply. Discussion appropriateness is 75.00% versus 89.06%, but its rubric checks logical consistency with the debate, not factual truth; that score alone is not evidence of robust speaker-aware comprehension.

Caveat for text-only turn-taking scores

The paper reports 49.22% and 98.44% turn-taking accuracy for its two text-only Gemini conditions, but it does not specify how generated text is mapped to the binary “spoke / stayed silent” label. Its word-timestamp rule is defined for audio output. We retain the reported values, but they are not documented as chunk-by-chunk turn decisions and cannot be reproduced from the text-baseline description alone.

These are the authors’ Table 3 results, not local experiments. The text-only reference is Gemini-3.1-Pro; it is distinct from the LLM judge used to score outputs and from the separately evaluated GPT-Realtime audio model. See paper Table 3 and Sections 5.1–5.2 and the repository’s scoring instructions.
