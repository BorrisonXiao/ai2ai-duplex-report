# DuplexOmni S1 empty-response investigation

[Findings and actual audio](https://borrisonxiao.github.io/ai2ai-duplex-report/study-progress.html#s1-empty).

The model is MuyeHuang/DuplexOmni, revision b8a5ff6395ae51460d0402424fbd3359614a901a, BF16. S1 includes its audio encoder and language model (called Thinker), plus Talker, MTP and Code2Wav. External S2 is disabled throughout.

The same three questions have 22 Thinker controls (including one short sky control), 16 speech conditions and nine ordinary answer-text controls. These are 47 condition records, not 47 distinct questions. The question-text and transcript controls supply oracle text and are not audio-only duplex baseline results.

Actual raw outputs distinguish model silence, response-format rejection, poor request recognition and waiting for disabled S2. Gain and a generic direct-answer prompt yield nonempty speech in all three combined-condition cases; all three still miss or contradict required source facts. The model also makes unsupported status claims with a correct transcript. No general repair or full-bank accuracy result is certified.

Each allocated job uses one H200 NVL 141 GB. Thinker-only stages use GPU 0; the speech stage shares Thinker/Talker/MTP/Code2Wav on GPU 0, then runs Parakeet ASR on GPU 0 after S1 exits. Oracle controls follow on the same S1 checkpoint, Thinker only. Language models use vLLM. Jobs are sequential and maximum active GPUs is one. The unallocated A100 request used zero GPU time. A diagnostic progress-counter bug stopped a partial speech run, which is preserved and excluded from complete-answer results; the cost remains included. The initial controls used 631 allocated seconds / 0.17528 GPU hours; native-history extensions and their current totals are recorded per job in progress.json. No CUDA OOM or two-GPU fallback occurred.

`progress.json` contains actual generations, independent speech transcripts, source-review explanations and per-job accounting. `code/` provides the diagnostic and source-review code. The earlier full-pilot context and verified reference passages remain linked from the report. Raw recordings and original code/data are preserved; these selected players include the adjusted questions and full-history model responses. Actual waveform playback is distinct from native model speech text, and waveform recognition is not a human listening rating.

Input adjustment targets request RMS amplitude 0.05, with peak capped at 0.95; gains are +2.92, +18.02 and +17.92 dB. Original question text/voice and earlier meeting audio remain unchanged. Buffered generation allows 40 silent continuation turns after the initial request, retaining full history. The actual longest text-shell and per-audio expansion check bounds 47,139 tokens against the 49,152-token context. The repaired wrapper's explicit progress index passed a CPU fixture; the shared evaluator's earlier 46 checks remain separate from experimental accuracy.

Native message-history extensions replay every 480 ms frame and retain the actual S1 responses. The greedy control hit a conservative context guard after repeated ASR text and did not reach the request. The released decoding settings (temperature 0.8 and maximum 999 tokens) completed the native prefill, but the model invented a Ukrainian-translation request in its own ASR and replied in Ukrainian. A generic meeting-listener role and Assistant wake-word condition are tested separately; the written-question branch is explicitly an oracle and is excluded from audio-only baseline claims.

The native history extensions are finished: greedy decoding failed before the request after ASR repetitions; released decoding settings completed both request branches, and the meeting-listener prompt completed two audio branches plus one written-question oracle. None supplies a complete source-supported answer, and no speech was synthesized in these native-history controls. The released bridge retains 150 turns (about 72 seconds) by default; the native full-history tests extend that setting deliberately. Total investigation allocation: 2505 seconds / 0.69583 GPU hours, maximum one H200 141 GB active; all jobs finished. This includes all failed/cancelled attempts. The earlier A100 pilot is accounted separately.
