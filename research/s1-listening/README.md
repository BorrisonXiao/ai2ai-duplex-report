# Controlled S1 listening

Compare two methods on the same two spoken questions at 5:09 and 9:21 using native 480 ms audio packets. Both use a common four-field format rule. Decode-and-clear freely generates ASR and any controls before ASR, stops before the unused speech suffix, then saves ASR with empty speech/control fields; it does not synthesize speech that would be discarded. Constrained listening forces those fields empty during generation. Both require a nonempty first speech fragment on the first silence packet after the complete question, then allow ordinary continuation and forbid S2 delegation. No answer words are prescribed. No special mode token, question transcript, reference transcript or answer is supplied. This is a controlled answer test; automatic turn timing is not evaluated. Both preserve observed native field orders and use the original short native prompt. No text cue is appended.

All history is retained while it fits, with a common ceiling of 1,250 audio/response pairs (600 seconds) and the 65,536-token context guard; overflow removes the oldest 200 pairs (96 seconds) at once to reuse the vLLM prefix cache between events, and actual retained times are recorded. Shortened history is not a full-history result. Request levels use the earlier fixed level-control recipe. Speaker enrollment audio is absent.

The saved response audio contains actual sequential Talker packets after the question. It is unpaced, has no real-time latency interpretation and requires independent transcription and source review. Partial or failed runs are not completed answers. The short sky controls are excluded from the four meeting outputs and the 105-question benchmark.

The 21:40 case was deferred because its native full prefix exceeds 65,536 tokens even with empty ASR fields, and a recent-history fallback would remove its listed evidence. Four meeting outputs completed; all missed their required source facts in both native answer text and independent speech transcripts. Question-only replays recover the first question with both methods; the effect of preceding history remains unresolved.

Each paired job requests one RTX PRO 6000 Blackwell 96 GB: all S1 components share GPU 0, then independent Parakeet ASR uses GPU 0 after S1 exits. S2 is disabled. The two method jobs may overlap, with a maximum of two GPUs active and no shared model service; stages within each job are sequential. Earlier calibration allocations used one H200 NVL 141 GB or one RTX PRO 6000 96 GB at a time. CPU checks and report publication use zero GPUs. Exact allocations include failed attempts in progress.json.
