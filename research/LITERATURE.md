## Scope & sub-questions

Incremental, revision-aware and speaker-aware reasoning in full-duplex spoken dialogue, emphasizing 2024–September 2026 primary papers and usable research artifacts.

- How do concurrent input, text, speech output and interaction control share time and parameters?
- Where does private reasoning run, and can new speech revise it?
- Which code, checkpoints, fine-tuning recipes and training corpora are actually released?
- Which benchmarks measure timing, corrections, speaker attribution and grounded task completion?
- Which natural or synthetic datasets preserve channels, overlap, timestamps and task state?
- Which parts of the March proposal are established prior work, and which questions remain open?

## Landscape summary

The literature supports several concrete paths beyond the original Moshi-based study. For a text reasoning backbone, MiniCPM-o 4.5 exposes a streaming encoder and lightweight speech decoder, while BayLing-Duplex expresses dialogue control in a standard autoregressive vocabulary. Lychee-FD retains native parallel modeling but separates deeper semantic, acoustic and control parameters. Realtime-Venus and DuplexOmni make asynchronous backend reasoning an explicit system component.

Moshi already has an LLM backbone. The architectural comparison is therefore about how time, concurrent streams and speech generation are represented, rather than whether a model uses an LLM. In particular, a text-only output vocabulary can coexist with continuous audio input and a separate speech decoder; “codec-free” usually describes the LLM interface, not necessarily the complete synthesizer.

The March proposal already cites Think while listening, now an ICLR 2026 paper. It directly studies early CoT and semantic sufficiency, while its DPO stage also addresses adaptive reasoning. The strongest remaining question in the reviewed evidence is how a model revises a hypothesis when a delayed constraint arrives from the relevant speaker amid overlap, or while a delegated job is still running. This is a synthesis of the reviewed sources, not a claim of exhaustive novelty.

Evaluation now extends well beyond single-turn spoken reasoning: τ-Voice measures grounded customer-service outcomes, FDB v2/v3 test corrections and tool use, and September’s Duplex-MPE directly targets multi-party addressing and silence. These suites complement VoiceBench and MMAU-Pro; a high score on one does not imply strong performance on another.

## Themes & consensus

- Time representation, speech decoding and reasoning location are separate design decisions: a decoder-only LLM can support either serialized or parallel duplex streams.
- Keeping acoustic generation away from text reasoning is a recurring strategy, implemented by separate speech decoders, hierarchy, frozen backbones or external reasoning models.
- Conversation timing, language competence, grounded tool execution and multi-party addressing require different evaluation conditions.
- Weights and inference code are much more common than fully reproducible training mixtures. Manifest, sample and gated releases need explicit labels.

## Open gaps & opportunities

### Speaker-conditioned revision under late evidence: determine whose correction should update which hypothesis while preserving timing.

Think while listening addresses early CoT/DPO; FDB v1.5 and Duplex-MPE address overlap/addressing. These reviewed sources do not jointly establish causal speaker-specific reasoning revisions. [2510.07497](https://arxiv.org/abs/2510.07497), [2507.23159](https://arxiv.org/abs/2507.23159), [2609.31948](https://arxiv.org/abs/2609.31948).

### Measure useful answer timing alongside correctness and commitment errors rather than rewarding a fast filler or an early wrong answer.

SRQA measures reasoning delay; FDB v3 separates first response, tool and completion latency; τ-Voice measures task success and voice interaction. Their metrics are complementary. [2510.07497](https://arxiv.org/abs/2510.07497), [2604.04847](https://arxiv.org/abs/2604.04847), [2603.13686](https://arxiv.org/abs/2603.13686).

### Invalidate stale backend work when a correction arrives after delegation and before result admission.

Realtime-Venus, NVIDIA frontend–backend and Context Spanning provide different delegation/injection mechanisms. Robust correction during this interval needs an explicit controlled test. [2609.13814](https://arxiv.org/abs/2609.13814), [2609.19334](https://arxiv.org/abs/2609.19334), [2609.33443](https://arxiv.org/abs/2609.33443).

### Construct natural-acoustic prefix supervision with stable session/speaker splits and auditable sufficiency/revision labels.

SmoothConv/DuplexConv and otoSpeech preserve channels or timing; SRQA/CoT construction uses synthetic speech. Existing corpus labels are not automatically reasoning-sufficiency ground truth. [2510.07497](https://arxiv.org/abs/2510.07497).

These are this review’s inferences, not proof of exhaustive novelty.

## Review method and limitations

Search angles covered native multi-stream models, serialized LLM decoders, codec-free text backbones, asynchronous delegation, reasoning under partial speech, interaction benchmarks, and natural/synthetic conversational data. Paper existence was verified through arXiv or publisher/venue pages; substantive descriptions use primary manuscripts. Availability was checked against official repositories and model/dataset cards. Repository release notes and cards can change after this date. No training, benchmarks, model downloads or provider calls were run.

This is a focused architecture and resource review, not an exhaustive survey or an independently reproduced leaderboard. Some newly posted papers have no located release; some code packages expose inference or fine-tuning rather than foundation training. Unknown authors/venues and artifact status remain explicit. Closed realtime APIs appear as comparators in benchmark papers, but their private internal architecture cannot be inferred from those results.

For a comparison, pin the model and harness revision, prompt, task split, judge, audio condition, playback/clock behavior and backend latency. Report response initiation, correct useful answer, tool request, task completion and interruption stop time separately. Include correctness and false commitments at each timing point, and distinguish natural recordings from TTS-generated speech.
