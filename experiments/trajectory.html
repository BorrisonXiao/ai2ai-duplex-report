Capture and interpretation
Real runs
The DuplexOmni driver now flushes events.jsonl during a run and exports a portable trajectory.json with embedded WAV clips on exit. Copy that JSON to your machine and load it above. A shared monotonic clock covers startup, S1, S2 and Talker.
S2 progress records received character counts and final answer text. Its internal reasoning text is not stored. Thinker calls currently return a complete response, so their tokens and spoken words have no measured alignment.
Two clocks to keep separate
Wall time answers when a request started, when a delta arrived and when an audio file became available. Audio content time answers where you are within a recording. The cursor links them using an explicitly labeled audition anchor.
The current controlled test submits whole audio turns, then returns whole WAV files. A true streaming trajectory also needs chunk input timestamps, codec emission times and actual playback timestamps; those are not inferred here.
Portable trace schema and export command
The viewer accepts duplex-trajectory/v1 JSON containing evidence, lanes, events, media, metadata and limitations. Events use start / end seconds and a lane ID; media use embedded data:audio/wav;base64,…, duration and an optional wall-time anchor. Remote media URLs are not fetched.
python scripts/trajectory.py exp/inference/duplexomni/audio_turn_system2_JOB_ID
Existing run folders without event logs export as summary_only. Their audio remains listenable, but the viewer shows no fabricated timeline.
Trace limitations
    This page is a local inspection tool. The hosted measured example publishes reviewed text and timing only. It contains no audio, private paths, model checkpoints or private reasoning. The optional synthetic demo uses invented timings and tones.
