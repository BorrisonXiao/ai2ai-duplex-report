Implementation roadmap

TODO and staged implementation plan

Build and evaluate natural participant questions for a separate duplex meeting assistant, then extend to document tools and preparation before requests.

Text questions and speaker-matched question audio have working pilots. Evaluation on a duplex model using the AMI insertions, broader audio coverage, independent human ratings and a learned action-timing policy remain unfinished.

Next work

  1. Continue expanding the question bank while improving source checks and reducing the need for Codex repairs.
  2. Add the cue to the older texts before further synthesis, then extend requester-matched TTS to a balanced selection from the new batch.
  3. Run the existing inserted questions through the duplex model and measure whether it notices the cue, answers the correct participant and uses the earlier discussion.

The list below tracks the broader implementation. Completed pilot checklists are evidence for individual steps; they do not mean the whole project is finished.

1. Expand the question bank2. Check difficulty and use of history3. Generate and insert requester-matched speech4. Evaluate the duplex model on the inserted questions5. Extend earnings calls to document tools6. Study preparation and learn when to act

Choices already made

  • The requester is an existing participant; the assistant is a separate listening agent.
  • Use only conversation history available before the question. Preserve uncertainty and the original speaker roles.
  • Include the spoken Assistant cue before audio evaluation.
  • Pause the meeting for the first question-answering tests, then test continued streaming.
  • Count questions by the facts requested. Alternative phrasings and repeated tests do not create extra questions.
  • Prioritize question quality and requester voice. Spoken answer synthesis remains deferred.
