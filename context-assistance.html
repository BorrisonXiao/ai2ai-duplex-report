What is already studied?

Yes—there is already closely related work. MSI-Bench tests a later assistant-directed request after group speech; GroupMemBench explicitly tests speaker-conditioned ambiguity; MultiTalk trains a full-duplex model for long multi-party conversations. The opportunity is narrower than “an assistant that overhears a meeting.”

[1] [2] [3]

Primary scope: proactive listening, assistance when asked

Using prior conversation to resolve a later instruction is different from interrupting the group with unsolicited advice. SocialMind and ProMediate cover adjacent proactive intervention settings; keep that branch optional.

[13] [14]

MSI-Bench

Overheard context → a later request

Its background-speech retrieval cases already require facts from another speaker. Use it as the closest task baseline, not evidence of an untouched problem.

A useful implementation starting point, not a promised full system

A public Moshi or MiniCPM-o backbone can serve as a reproducible baseline while MultiTalk’s checkpoint release remains unverified. Pair native audio with a transcript + diarization + speaker-scoped memory control. Neither approach has yet been implemented for this narrowed project.

Keep evaluation data held out

MSI-Bench, MultiTalkBench, ContextDialog and the released GroupMemBench questions are evaluation resources, not default training sets. MISeD, QMSum and some MultiTalkBench examples share underlying meeting corpora: deduplicate and split by meeting and participant before training. Reconstructing new speech or clarification labels is proposed work, not an existing release.

Implications for the narrowed project

Proposed evaluation

Does the overheard context actually change interpretation?

Hold the final request fixed; swap a relevant earlier speaker, referent or corrected plan. Compare final-request-only, full-transcript, speaker-aware memory and native-audio inputs. Score the intended referent and evidence source, not just fluent answer quality.

[1] [2] [5]
Proposed evaluation

When should the assistant ask instead of guess?

Include context that resolves an ambiguous request, context that leaves two viable interpretations, and missing evidence. Score targeted clarification, successful completion after the reply, unsupported guesses and unnecessary questions.

[4] [2]
Proposed evaluation

Can the intended answer change while the model is listening or speaking?

Use timestamped prefixes only. Inject a correction before answer onset and during the answer; measure memory-update delay, stale spoken commitments, correction uptake and interruption recovery. This retains the original synchronization concern.

[3] [7]
Proposed evaluation

Can it stay quiet and respect the audience?

Pair assistant-directed requests with human-to-human versions. Evaluate false activation separately from answer correctness, and test whether useful private context is disclosed to an unauthorized listener.

[8] [1] [12]

A scoped initial recipe: meeting-grounded QA from MISeD/QMSum + speaker-conditioned ambiguity from GroupMemBench + answer/clarify decisions inspired by ASK-QA, evaluated with MSI-Bench and duplex restraint controls. Natural meeting prefixes still need assistant-directed requests, intended referents, evidence timestamps and human-validated clarification labels. Establish consent and permissible retention before using new meeting recordings.

Novelty boundary

The reviewed resources already establish multi-party context use, speaker-dependent interpretation and proactive intervention individually. A defensible candidate contribution is their causal combination in synchronized speech: a later request grounded in a real conversation, clarification when needed, and revisions without inappropriate interruptions or disclosures. This is a review-based hypothesis, not an exhaustive novelty claim.

Paper notes

Fifteen verified papers, selected for task proximity rather than popularity. Expand for concise method, result and limitation notes. Months are retained when the publisher supplies no exact publication day.

MSI-Bench: Evaluating Multi-Speaker Voice Interaction for Collaborative AI Agents [1]
Problem
Voice assistants must bind facts, permissions and instructions to the right speaker.
Method
Short multi-person audio scenes end in an assistant-directed request; atomic rubrics and tool-call checks score the response.
Author-reported result / resource
1,152 cases, split evenly between English and Mandarin. English all-pass rate: Gemini 3.1 Pro 66.8%; Qwen3-Omni-30B 34.0% (Table 1).
Relevance
Closest benchmark to overhearing a group and acting on a later handoff.
Limitations / review assessment
Scripted TTS, mostly turn-based evaluation; separate restraint probes are not a continuous meeting simulation.
Primary manuscriptCode (MIT) Audio / cases (CC BY 4.0)
GroupMemBench: Benchmarking LLM Agent Memory in Multi-Party Conversations [2]
Problem
An identical group-chat question can mean different things depending on who asks.
Method
Graph-generated enterprise conversations; queries include asker identity and six memory categories, including term ambiguity and abstention.
Author-reported result / resource
Hindsight: 46.01% overall / 37.74% term ambiguity; BM25: 43.22% / 14.15% (Table 2).
Relevance
Closest formulation of speaker-conditioned disambiguation; useful text-only control.
Limitations / review assessment
Synthetic text; no speech timing or interactive clarification. Queries are adversarially filtered against a retrieval solver. Paper and data card differ on corpus counts.
Primary manuscriptCode / questions Conversation data
MultiTalk: Scaling Full-Duplex Speech Models to Long, Multi-Party, Bilingual Conversation [3]
Problem
Duplex models need long-history speaker tracking and appropriate participation in groups.
Method
Moshi-derived Moshi-MTB trained in two phases: bilingual dyadic pretraining, then multi-party fine-tuning; parallel audio and word-aligned text.
Author-reported result / resource
MultiTalkBench final score: Moshi-MTB 13.15, MiniCPM-o-4.5 11.05, human reference 68.74 (Table 2).
Relevance
Most directly relevant trained full-duplex model and released multi-party speech training data.
Limitations / review assessment
Benchmark replaces a human participant, rather than exclusively testing a later assistant request. Persona prompts are constructed offline from transcript excerpts; audit future-context leakage.
Primary manuscriptPretraining data Multi-party fine-tuning data Benchmark Card-linked code URL
Data-Centric Improvements for Enhancing Multi-Modal Understanding in Spoken Conversation Modeling [4]
Problem
Spoken requests can remain ambiguous even after reading the preceding dialogue.
Method
DAMSEL audio-model customization and ASK-QA: TTS-rendered Abg-CoQA with narrated knowledge, dialogue history and simulated clarification exchanges.
Author-reported result / resource
ASK-QA reports 221.8 speech hours; 5,985 / 500 / 1,345 train / validation / test conversations (§3.1).
Relevance
Direct source for the answer-versus-clarify behavior missing from many turn-taking tests.
Limitations / review assessment
Narrator/user/assistant voices are not a natural multi-party meeting. Dedicated ASK-QA audio, code and trained weights were not located.
Primary manuscriptUnderlying text clarification data
Efficient Data Generation for Source-grounded Information-seeking Dialogs: A Use Case for Meeting Transcripts [5]
Problem
Users need follow-up answers grounded in noisy, lengthy meeting transcripts.
Method
LLM-generated information-seeking dialogues over QMSum meetings, with human validation, correction and attribution spans.
Author-reported result / resource
432 retained dialogues over 225 meetings; 4,161 validated QA pairs, split 2,922 / 611 / 628 (Tables 2, 14).
Relevance
Closest reusable meeting-grounded assistant dialogue supervision, including follow-up questions.
Limitations / review assessment
Text-only access to a completed meeting; no assistant-addressing or real-time clarification policy.
Primary manuscriptDataset
MP-Bench: Evaluating Voice Agents as a Multiparty Conversation Participant [6]
Problem
A voice agent needs to know whose turn it is and resolve references across participants.
Method
Three simulated humans plus an agent in discussion and turn-based games; behavioral and comprehension tasks.
Author-reported result / resource
Twelve evaluated agents; turn-taking, response appropriateness and complementary multi-party comprehension are evaluated.
Relevance
Useful speaker-attribution and reference-resolution diagnostic, distinct from Duplex-MPE.
Limitations / review assessment
Clean synthetic speech without overlap; short scenarios. Repository URL returned 404. PDF abstract says 33% where landing-page abstract says 22%; neither is plotted.
Primary manuscriptPaper-linked repository (404 at check)
Duplex-MPE: Benchmarking Multi-Party Interaction in Full-Duplex Dialogue [7]
Problem
A duplex agent should respond when addressed, not whenever someone in the room speaks.
Method
Continuous synthetic multi-person streams; paired explicit and implicit invitation cases test onset, silence and floor release.
Author-reported result / resource
2,000 paired scenarios / 4,000 streams; already included in the broader duplex review.
Relevance
Essential addressing and conversational-restraint guardrail for ambient listening.
Limitations / review assessment
Does not by itself establish long-history intent disambiguation; dedicated evaluation audio/code release was not located.
Primary manuscript
Speak or Stay Silent: Context-Aware Turn-Taking in Multi-Party Dialogue [8]
Problem
A pause or mention of the assistant is not necessarily an invitation to speak.
Method
Text LLM plus LoRA / reasoning-trace SFT predicts SPEAK or SILENT for a target participant at utterance boundaries.
Author-reported result / resource
More than 120K labeled decisions from AMI, Friends and SPGISpeech; authors report up to 23 percentage-point balanced-accuracy improvement.
Relevance
Released training recipe for contextual participation, separate from answer generation.
Limitations / review assessment
Human next-speaker behavior supplies labels, not optimal assistant usefulness. Labels must not be exposed as input; split by meeting to avoid shared-history leakage.
Primary manuscriptTraining / inference code (main branch) Decision data Qwen3-8B AMI LoRA adapter
ELITR-Bench: A Meeting Assistant Benchmark for Long-Context Language Models [9]
Problem
Meeting assistants must answer inferential queries and conversational follow-ups over ASR errors.
Method
Manually authored meeting questions; standalone QA and follow-up conversation settings, with simulated ASR-noise variants.
Author-reported result / resource
271 manually crafted QA pairs; evaluates long-context LLMs and examines agreement between model and human judges.
Relevance
Useful meeting QA and noisy-transcript baseline; conversation version tests follow-up references.
Limitations / review assessment
Transcript-only completed meetings; not a streaming speaker-addressing test.
Primary manuscriptData / results / evaluation
Does Your Voice Assistant Remember? Analyzing Conversational Context Recall and Utilization in Voice Interaction Models [10]
Problem
Voice models lose facts that appeared earlier in speech-only history.
Method
MultiDialog human dialogue histories with generated, speaker-adaptive TTS recall questions and supporting utterances; native recall and RAG analyses.
Author-reported result / resource
2,612 QA pairs over 653 retained two-speaker dialogues (Table 1).
Relevance
Isolates spoken-context retention before adding group-level ambiguity.
Limitations / review assessment
Dyadic, test-only recall data; full histories require the underlying MultiDialog corpus.
Primary manuscriptQA data (CC BY-NC 4.0) Project Underlying histories
QMSum: A New Benchmark for Query-based Multi-domain Meeting Summarization [11]
Problem
Different meeting attendees need different subsets of a meeting summarized.
Method
Query-based summaries with manually selected relevant transcript spans across product, academic and committee meetings.
Author-reported result / resource
1,808 query-summary pairs from 232 meetings (Table 1).
Relevance
Evidence-localization supervision and meeting-grounded pretraining; also the source of MISeD.
Limitations / review assessment
Summaries are not clarification labels; transcripts may contain future evidence relative to a live request. Audio must be obtained from source corpora.
Primary manuscriptQueries / summaries / spans
MuPPET: A Benchmark for Contextual Privacy of LLM Assistants in Multi-Party Conversations [12]
Problem
Information appropriate for one user may be private to others hearing the answer.
Method
Workplace group chats, target-user memories and final assistant requests; score sensitive-information leakage alongside useful content.
Author-reported result / resource
562 synthetic multi-party workplace conversations; released seeds, memories, conversations and evaluation scripts.
Relevance
Privacy control for deciding what overheard context can be disclosed, not merely retrieved.
Limitations / review assessment
Text-only synthetic interactions, not consent-aware ambient speech capture.
Primary manuscriptData / evaluation code
SocialMind: LLM-based Proactive AR Social Assistive System with Human-like Perception for In-situ Live Interactions [13]
Problem
People may benefit from discreet help during live interactions with other people.
Method
Multimodal sensing of speech and social cues, persona-aware LLM suggestions and proactive visual updates on AR glasses.
Author-reported result / resource
Evaluation on three public datasets and a 20-participant user study.
Relevance
Existing ambient, proactive social-assistance system: broad proactive-help claims are not new.
Limitations / review assessment
Visual coaching, not native speech-to-speech duplex or later-request disambiguation. Dedicated system release was not located.
Primary manuscript
ProMediate: A Simulation Testbed for Evaluating Proactive Mediation in Multi-Party Negotiation [14]
Problem
An unsolicited mediator must choose when and how to intervene in group negotiation.
Method
Simulated multi-party negotiation with plug-in mediators; consensus and socio-cognitive intervention evaluation.
Author-reported result / resource
Social mediator improves consensus change over a generic mediator in the authors’ hard setting.
Relevance
Useful only if scope expands to unsolicited assistance or meeting facilitation.
Limitations / review assessment
LLM simulation and text interventions; not evidence of live speech synchronization.
Primary manuscriptSimulation / evaluation code
Proactive Hearing Assistants that Isolate Egocentric Conversations [15]
Problem
A wearable should isolate the wearer’s conversation rather than all nearby speech.
Method
Self-speech beamforming anchors a slow conversation-embedding model and a fast streaming source-extraction model.
Author-reported result / resource
Real-world binaural test recordings: 11 participants, 6.8 hours (§4).
Relevance
Front-end resource for distinguishing a user’s conversation from an unrelated bystander group.
Limitations / review assessment
Acoustic conversation isolation, not language-level instruction interpretation or assistant answer generation.
Primary manuscriptCode / model / data instructions
