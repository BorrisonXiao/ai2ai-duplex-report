Definitions, caveats and sources

Coverage of the published evaluation protocol, not every task that could be built from the data. Model interface describes the intended input/output route; it does not imply that every capability of that model is evaluated.

Multi-party means a group setting, in text or audio. Synthetic describes the conversation/voice material; Mixed combines generated and human material. Target model: Text = text input/output; Audio→text = audio input, text/JSON output; Voice = voice interaction; Duplex = concurrent listening and speaking. Alternative adapters and text controls are listed below.

Content = semantic response scoring; Tools = call correctness; Timing = participation or response timing; User interruption = yielding/recovery when a user interrupts; Backchannels = generation or tolerance of brief acknowledgments; Speech quality = acoustic/prosodic scoring. A Yes does not imply comprehensive coverage. MSI bystander interference is distinct from directed user interruption. Source check: 2026-10-19.

MultiTalkBench

Multi-speaker setting
Yes: real multi-party recordings; the model replaces a designated named participant.
Data origin
Human recordings from meeting, dinner-party, in-car and telephone corpora; constructed alignments/persona prompts. Distinct from synthetic MultiTalkPT/FT training data.
Input, protocol and model interface
Long audio conversations for full-duplex speech models; target-participant outputs are aligned and inserted into the peer transcript for offline judging.
Semantic response scoring
Yes: response quality, speaker/state tracking, group interaction and role-specific contributions.
Tool-call scoring
No dedicated function-call execution/argument metric.
Duplex and timing coverage
Limited: mechanical first-to-last speech-span participation score; content/role judgments. The paper explicitly excludes direct latency/interruption-timing measurement.
What the scores do not establish
Its scores do not certify barge-in stop latency, backchannel timing, acoustic fluency or tool use, despite targeting full-duplex models.

At a glance

MultiTalkBench is a held-out, long-form speech-to-speech benchmark. Each row pairs a real meeting recording with a designated participant, that participant’s aligned speech, and persona/context material. The evaluated model takes the designated participant’s role while the other participants remain part of the conversation.

The release describes tests of long conversations, multi-party participation, and bilingual ability. It includes explicit probes for long-range entity tracking and topic coherence alongside addressee selection and turn-taking. The scope table above distinguishes those content and participation judgments from direct interruption latency, acoustic fluency, and tool-use evaluation.

What is in the release

The pinned snapshot includes the official test Parquet shard, JSONL and CSV metadata, full meeting audio, word- and sentence-level alignments, target-speaker persona prompts, meeting profiles, and transcript context. The metadata and Parquet row counts agree. Each sample represents one meeting and target-participant pair; several participants from one meeting share meeting-level material.

Inputs and identity

audio identifies the stereo meeting recording. target_speaker and persona specify whose role the model fills. The alternative minimal prompt supports a persona-off condition.

Reference and context

alignment provides sentence and word spans for the target participant. meeting_profile and transcript_context provide meeting-level material used by the benchmark pipeline.

Keep test data held out

This is the MultiTalkBench test split. The separate MultiTalkFT release is a fine-tuning corpus, not this benchmark’s test set. The workspace already contains a 158 MB MultiTalkFT pilot with manifests, a 100-row preview, and three English audio examples; it is not a complete corpus. The benchmark data and the training pilot remain in separate directories.

Local release validation

The complete local copy was checked against Hugging Face commit d7188c179603db8566c50b6e43af5c8a1e7678ba. Validation covers the downloaded inventory and sizes, row agreement across the three tabular views, every referenced asset, full FLAC decoding, and alignment bounds.

Aligned text

Referenced assets

Every audio, alignment, persona, meeting profile, and transcript-context path exists; profile IDs match sample meeting IDs.

The repository snapshot is 5,191,617,996 bytes (5.19 GB decimal; about 4.83 GiB). The Parquet shard stores an audio payload column, so its metadata and non-audio columns were read without loading the multi-gigabyte audio column into memory. The separate audio files were all decoded in bounded blocks.

No model evaluation is claimed here

This page audits the released test data only. No local model inference, benchmark scoring, or quality claim has been produced from this snapshot.

Reproduce the data checks

From the project workspace, download the same pinned snapshot and run the validator and preview exporter:

python scripts/download_assets.py multitalkbench
envs/data/bin/python scripts/validate_multitalk_bench.py
envs/data/bin/python scripts/export_multitalk_bench_preview.py
python site/scripts/build_multitalk_bench.py

The site hosts only two short, attributed excerpts and the integrity record; it does not mirror the full 5.19 GB release into GitHub Pages.
